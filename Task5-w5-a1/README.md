# Task 5 — The Polite Scraper Microservice (Week 5)

## 📌 Overview & Goal
In real-world AI engineering, production RAG (Retrieval-Augmented Generation) systems require reliable, well-structured, clean data gathering pipelines. **The Polite Scraper** is a Python data-gathering microservice built around a 5-stage processing pipeline (**`fetch ➔ parse ➔ extract ➔ clean ➔ structure`**) equipped with standard web politeness controls (`robots.txt` enforcement, User-Agent identification, rate-limiting delays, exponential backoff retries).

The output generated by this scraper (`corpus.jsonl`) forms the **foundation corpus for next week's Week 6 RAG Vector Database system**.

---

## 🏗️ The 5-Stage Pipeline Architecture

```text
+-------------------+     Robots Check     +-------------------------+
| Target Web Site   | <------------------ | 1. FETCH (Polite Client)|
| (books.toscrape)  | ===================> | User-Agent + Rate Limit |
+-------------------+      HTML Pages      +-------------------------+
                                                        |
                                                        | Raw HTML
                                                        v
+-------------------+     Cleaned Schema    +-------------------------+
| 5. STRUCTURE      | <-------------------  | 2. PARSE ➔ 3. EXTRACT   |
| (corpus.jsonl)    | (Pydantic Validated)  | ➔ 4. CLEAN (BS4/LXML)   |
+-------------------+                       +-------------------------+
```

### Stage 1: FETCH (Politeness Layer)
* **`robots.txt` Verification:** `RobotsChecker` parses the target origin's `/robots.txt` via `urllib.robotparser.RobotFileParser` before issuing requests.
* **Polite User-Agent Header:** Every HTTP request includes an explicit, non-spoofed User-Agent header:
  `User-Agent: FlyRank-PoliteScraper/1.0 (+https://github.com/Rytnix786/first-api-endpoint; contact@flyrank.ai)`
* **Rate Limiting & Delays:** `PoliteFetcher` enforces a configurable sleep interval (`--delay` default 1.0s) between successive requests to prevent server overload.
* **Exponential Backoff:** Retries 429 and 5xx status codes up to 3 times with exponential backoff (`2^attempt` seconds).

### Stage 2: PARSE
* Parses raw HTML documents using `BeautifulSoup4` with `lxml` / `html.parser` tree builders.

### Stage 3: EXTRACT
* Extracts key document fields: product `title`, raw price string, rating CSS class, availability badge, breadcrumb category, and detail description text.

### Stage 4: CLEAN
* **Currency Normalization:** Strips currency symbols (`£`, `$`, `EUR`) and converts strings like `"£51.77"` to float `51.77`.
* **Rating Normalization:** Converts word classes like `"star-rating Three"` into integer ratings (`3`).
* **Text Sanitation:** Strips trailing whitespace, normalizes non-breaking spaces (`\xa0`), and cleans HTML artifacts.

### Stage 5: STRUCTURE (RAG Corpus Serialization)
* Validates every record against the Pydantic `ScrapedProduct` model.
* Exports validated objects to newline-delimited JSON (`corpus.jsonl`) and formatted JSON array (`corpus.json`).

## 🚀 Installation & Usage

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Run Automated Unit Tests
```bash
python -m unittest test_polite_scraper.py
```

### 3. Execute Scraper Pipeline
```bash
python polite_scraper.py --url http://books.toscrape.com/ --limit 10 --delay 1.0 --output corpus.jsonl
```

### CLI Arguments
* `--url`: Base target URL (Default: `http://books.toscrape.com/`).
* `--limit`: Maximum number of product pages to crawl (Default: `5`).
* `--delay`: Politeness delay between requests in seconds (Default: `1.0`).
* `--output`: Output corpus file path (Default: `corpus.jsonl`).
